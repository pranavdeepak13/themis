# Decisions

Format: date, decision, reason. Newest last within each phase.

## Phase 1

1. **Branch name `main`.** The fresh repo started on `master`; renamed to `main` (no commits yet) to match the plan.
2. **Python 3.12, uv, hatchling build.** `requires-python >=3.12`; uv resolved a 3.12/3.13 interpreter. Ruff line length 120 because transcript field names and Rich strings are long.
3. **Profile naming.** `~/.claude` is named `default`; `~/.claude-X` is named `X`. Aliases come from `~/.themis/config.toml` `[aliases]`. A directory is a profile only if it has `projects/` or `settings.json` (so `~/.claude-shared` is excluded).
4. **Assistant usage is deduplicated by `message.id`.** One API message is written as one line per content block with identical usage. Summing per line roughly doubles token totals. Verified on real data (no inconsistent repeats).
5. **Subagent tokens count toward session totals** and are also exposed separately as `subagent_tokens`. Context percent ignores sidechains.
6. **Tool calls deduplicated by `tool_use.id`**, so resumed or repeated lines cannot inflate counts.
7. **Context window is inferred.** The model id cannot tell 200k from 1M (both auto-compaction thresholds appear for the same model). Window = config table match (default 200k); if observed context exceeds it the window is treated as 1M. Consequence: a 1M-window session that never passed 200k shows an inflated percent. Users can override per model in `config.toml` `[context_windows]`. Percent is computed at display time, not cached, so config changes apply immediately.
8. **Cost is computed at display time** from cached per-model token buckets and the price table (`[prices.<family>]` in config; defaults for opus, sonnet, haiku). It is always labelled an API-equivalent estimate. 1-hour cache writes use the 1h rate, the rest the 5-minute rate. The price table is a placeholder to be kept current by the user; unpriced models mark the estimate incomplete rather than guessing.
9. **Topic priority:** `custom-title` (rename) > last `ai-title` > `summary` entry > first meaningful prompt > first slash command. A typed prompt beats a bare command. Wrappers (`system-reminder`, `local-command-*`, `task-notification`) are skipped and tags stripped; all topics pass through redaction and are cut at 120 characters.
10. **Memory writes:** a Write, Edit, MultiEdit or NotebookEdit whose target file name is `CLAUDE.md`, `CLAUDE.local.md` or `MEMORY.md`, or whose path has a component named exactly `memory`. Known false positive: source directories named `memory/`. Accepted to match the spec.
11. **Compaction count** = `compact_boundary` system entries.
12. **Cache validity** = schema version plus a signature of the transcript (size, mtime) and the whole session file set (count, total bytes, newest mtime), so new subagent or file-history files invalidate it. No SQLite. Cache entries for vanished sessions are pruned (only inside `~/.themis/cache`). Writes are atomic (temp file then rename).
13. **Process pool only for 6 or more cache misses**; below that, parsing inline avoids spawn cost. Warm path is single-process cache reads.
14. **`THEMIS_HOME`** overrides `~/.themis` so tests never touch real state.
15. **Related files** include `todos/<id>*` and `debug/<id>*` even though they are absent on this machine, to stay correct for older layouts. Project-level `memory/` is shared across sessions and excluded from a session's file set (matters for delete in Phase 2).
16. **Pre-commit guard** is `scripts/check_no_transcripts.py`, installed by `scripts/install-hooks.sh` (also usable through `.pre-commit-config.yaml`). It rejects any `.jsonl`, any path inside a Claude profile directory, absolute home-directory paths into `.claude*` in content, and transcript-shaped lines. `*.jsonl` is also gitignored; fixtures are generated into temp dirs at test time.
17. **Deferred modules:** `sessions/actions.py`, `sessions/search.py`, resources, registry, advisor, reports and UI packages exist as empty packages only; they belong to later phases. `audit.py` is implemented now because rule 1 depends on it.
18. **CLI table** shows the same data as `--json`; `--json` emits the full summary plus derived fields (`context_percent`, `cost_estimate_usd`, `cost_estimate_note`).

## Phase 2

19. **UI is sections inside one screen**, not one Textual `Screen` per section. A persistent shell (header, profile tabs, left nav, footer) hosts a `ContentSwitcher`; Sessions is a real pane, the other six are `PlaceholderPane`s registered for Phase 3 and 4. Reason: the profile bar and nav must persist, and modals stay simple.
20. **Core/UI split for rule 8.** All file work is in `themis/sessions/` (`actions.py`, `meta.py`, `search.py`, `timeline.py`, `export.py`, `retention.py`, `query.py`). The UI imports those and never opens a file. Filtering and sorting (`query.py`) are pure functions so they are testable without Textual. Clipboard is `themis/clipboard.py` (pbcopy) plus Textual's OSC 52 copy.
21. **`cleanupPeriodDays` verified in the installed Claude Code (2.1.311) settings schema:** positive integer, minimum 1, default 30 ("0 is rejected"). No profile on this machine sets it, so the default applies and the banner says "default". Sessions from desktop surfaces (`entrypoint` `claude-desktop`) are exempt from the sweep unless `desktopSessionCleanupPeriodDays` is set, so they are never flagged. A session is "at risk" when `days - age <= retention_warn_days` (config, default 7), age from the transcript mtime, since the sweep goes by file age. The public docs page did not mention the key, so the binary's schema text was the source.
22. **Restored and copied files get fresh mtimes.** Because retention goes by file age, preserving an old mtime would let Claude Code purge the restored or copied session at its next start. "Last active" in Themis comes from transcript timestamps, so it is unaffected.
23. **Confirmation tokens.** Delete and move require the first 8 characters of the session id (move because it deletes the source). Bulk delete requires typing `delete N`. Archive, restore, copy, export and tag need a plain confirm (token `confirm` at the API level, a Confirm button in the UI). Every action function takes `confirm` and `dry_run`; the modals are built from the dry-run plan.
24. **Delete safety.** The file set is re-walked at execution and compared with the plan (size and mtime per file); any change aborts. Refused: symlinks, any real path outside the profile directory, any file modified in the last 120 s, unsafe session ids. Only directories owned by the session (`projects/<enc>/<id>/`, `file-history/<id>/`, `session-env/<id>/`) are removed, and only when empty. Project-level `memory/` is never touched. The cache entry is dropped too. Verified on real data: Themis refused to delete the live session it was running in.
25. **Archive format.** `~/.themis/archive/<profile>/<session-id>.tar.gz` plus `<session-id>.manifest.json` (sizes and sha256 per file). Verified after writing. Restore validates every member against the manifest, rejects absolute or `..` paths, refuses to overwrite anything, and checks sizes and hashes. Archive never deletes the original; after a single archive the UI offers the normal delete modal as a separate confirmation. "Archive all at risk" archives only.
26. **Copy/move** write the same relative paths into the target profile (same encoded-cwd directory, so `claude --resume` works there). Move = copy, then delete the source with the delete token; if the delete step fails the copy is rolled back.
27. **Rename and tags** live in `~/.themis/meta.json` (`sessions["<profile>/<id>"]`), atomic writes, unknown top-level keys preserved for Phase 3 resource tags. Rename is a Themis display name only; it does not write a `custom-title` into the transcript (rule 3).
28. **Full-text search** streams each main transcript line by line (subagent transcripts are not searched). A raw-bytes prefilter skips non-matching lines; queries with quotes, backslashes or non-ASCII skip it and are slower (about 6 s for 206 MB) but still cancelable. Text is redacted before the window is cut, so a secret split by the snippet boundary cannot leak, and a query that is itself a secret matches nothing. Caps: 3 hits per session, 200 total. It searches the sessions that pass the current filters, newest first.
29. **Export** writes redacted markdown to `~/.themis/exports/<profile>/`, main chain only; tool output is optional and truncated to 2000 characters each.
30. **Timeline** is built on demand for the selected session when the Timeline tab is open (streamed, cancelable, capped at 5000 rows), one row per API message, with per-turn input-side context and output tokens.
31. **`themis` with no command opens the UI; `themis web [--port]`** serves it with textual-serve on 127.0.0.1 only (host is deliberately not configurable). The served command is `python -m themis.cli`, which runs the same app. Default port 8765.
32. **Responsive layout.** Below 150 columns the detail pane stacks under the table. The table is about 120 columns wide with all ten columns; on narrower widths it scrolls horizontally.
33. **Resume launcher.** `resume_launcher` in `config.toml` is a shell template containing `{command}`; with none set the modal offers copy only. The command is shell-quoted where needed.

## Phase 3

34. **Inventory is one read-only scan** (`resources/scan.py`) producing flat `Resource` records with kind, origin (user, synced, plugin, project), path, realpath, symlink and broken flags, content hash, frontmatter, token estimates and an `extra` dict. Bodies are read on demand (`reader.py`, redacted). Project-level resources come from the working directories found in session summaries that still exist; `<cwd>/.claude` is skipped when it is itself a profile directory (the default profile is `~/.claude`).
35. **Token estimates** use 4 characters per token (`fsutil.CHARS_PER_TOKEN`) and are labelled estimates everywhere. Startup cost = name plus description; full cost = whole file. CLAUDE.md counts whole at startup.
36. **Frontmatter parser is a small YAML subset**, not a YAML dependency. A skill is valid with a description (the name defaults to its directory name); agents need name and description; commands need nothing. Real data: several project skills have no frontmatter, so the doctor reports them as warnings.
37. **Scope classification** (`scopes.py`): union-find over same kind, origin and name, joining entries with the same realpath or the same content hash. Class size 1 = profile-only, 2 to N-1 = shared, N = global (N = all discovered profiles; with two profiles a link in both is global). Drift = more than one class for a name. Copy = same content at different real paths. Only user and synced skills, commands and agents are classified; plugin and project resources are labelled by origin. The default `~/.claude` profile counts toward N, so the shared set here is "shared" not "global".
38. **Usage join** (`usage.py`) matches transcript names to resources: exact, or `:name` suffix for namespaced skills and commands, `_name` suffix for plugin MCP servers (`plugin_<plugin>_<server>`). "Last used" is the end time of the latest session that used it; sessions are not stored per profile, so a profile-filtered count has 0 sessions.
39. **Settings writes** (`resources/settings.py`): plugin toggle sets `enabledPlugins[id]`; MCP toggle edits `disabledMcpServers` in `.claude.json` for user-scope servers only (mechanism verified in the 2.1.311 binary). Plugin servers and project `.mcp.json` servers have no toggle in Themis and the UI says why. Every write: dry run with unified diff, confirmation token `confirm`, backup to `~/.themis/backups/<profile>/<file>.<timestamp>`, atomic replace preserving file mode, audit entry. The MCP diff shows only `disabledMcpServers`, never the rest of `.claude.json`.
40. **Settings editor** shows `settings.json` with secret values masked. On save, any value still equal to the mask is restored from the original at the same JSON path; a mask where no original value exists is rejected. Validation: valid JSON object, `permissions`/`hooks`/`enabledPlugins`/`env` are objects, permission lists are lists of strings. Diffs are computed on redacted text.
41. **Rule 1 now lists `resources/symlinks.py`** next to `actions.py` and `settings.py`, because promote creates symlinks in profile directories and the shared directory. Same contract: dry run, token, backup, audit.
42. **Promote** (`symlinks.py`): the canonical directory is `shared_dir` from config, else the root existing symlinks already point into (`~/.claude-shared` here), else `~/.themis/shared`. Layout `<root>/{skills,commands,agents}/<entry>`. Identical copies are moved to `~/.themis/backups/promote-<timestamp>/<profile>/...` and replaced by symlinks. A drifted copy is never overwritten unless the caller passes `prefer` (a profile, or `shared`); the plan shows the diff and the UI asks which side wins. Only top-level user entries are promotable; plugin, project, synced and namespaced entries are refused.
43. **Resource tags** live in `meta.json` under `resources["<kind>/<name>"]`, shared across profiles, alongside session metadata.
44. **MCP health** runs `CLAUDE_CONFIG_DIR=<dir> claude mcp list` (60 s timeout) from a button or explicit call only. Output is redacted before parsing. Verified once against the real CLI; claude.ai connectors show up there but are not in any config file.
45. **Doctor** is read-only: broken links, bad frontmatter, duplicate names (within the same origin and place), unreadable or invalid JSON, plugins with unknown marketplace, missing install directories or not installed, marketplaces with a missing install location, hooks pointing at missing scripts, orphan project directories, large transcripts (`large_transcript_mb`, default 100). Real-data corrections made: `@synced` plugins are app-managed and skipped; `$CLAUDE_PROJECT_DIR` hooks are not checkable at user level; duplicates only count within one origin.
46. **UI** adds Skills, Agents, Commands, Plugins, MCP, Hooks, Settings, Compare and Doctor sections (Insights stays a placeholder for Phase 4). One `ResourcePane` serves the six list sections (rows grouped across profiles via `resources/view.py`), so panes never open files; they call core. Resource data loads once in a worker (`resources/store.py`) and is reloaded after a write. The top profile bar filters every section except Compare.
47. **Cache race fixed.** The Sessions pane and the resource loader both call `load_sessions` in threads; temp files were named with the PID only, so two threads collided (`FileNotFoundError`). Temp names now include the thread id in the cache, meta and settings writers. Regression test added.
48. **Registry follows ARD v0.91** (Proposal, 26 Aug 2026), checked against the spec page, `spec/ard.md` Appendix C, `spec/schemas/ard-entry.schema.json` and `ard.openapi.yaml` in `ards-project/ard-spec` (read 2026-10-27 after the user allowed github.com and raw.githubusercontent.com in the project's `.claude/settings.json`). Identifier pattern from the schema: `^urn:air:[a-zA-Z0-9.-]+(:[a-zA-Z0-9._-]+)+$`. Themis uses `urn:air:<publisher>:<kind>:<scope>:<name>`: the publisher is a fully qualified domain (`--publisher`, default `themis.local`, the same placeholder style Observal uses; single-label hosts and IPs are rejected), the kind (`skill`, `agent`, `command`, `mcp-server`, `plugin`) sits in the multi-segment namespace so a skill and a command of one name differ, scope is `user`, `plugin.<name>` or `project.<dir>-<8 hex of path>`. Names outside `[A-Za-z0-9._-]` (`:`, `@`, spaces) become `-` plus a `.h<8 hex>` hash suffix of the original name, so the identifier is legal and distinct but not reversible. Profile, path and symlinking do not affect it. Verified on the real inventory: 228 entries, none schema-illegal, no duplicates.
49. **Manifest (`ard.json`)**: `{"entries": [...]}` plus a `themis` top-level member (ARD ignores other top-level members). Each entry has `identifier`, `displayName`, `type` and exactly one of `url` (file URL for skills, agents, commands) or `data` (redacted MCP config, plugin facts). Skills use `application/agent-skills+md` (the spec page; Observal's ADR uses `application/ai-skill+md`), MCP servers `application/mcp-server-card+json`; agents, commands and plugins have no registered type and use `application/vnd.themis.claude-*` placeholders (Observal does the same with `vnd.observal.*`). Themis facts live under `metadata.themis`. Drifted copies share one identifier with `variants`. Not generated: `representativeQueries` (SHOULD, 2 to 5), `trustManifest`, `capabilities`. Written to `~/.themis/registry/ard.json`, not served at `/.well-known/ard.json` (Themis opens no listener beyond the UI).
50. **Search follows ARD `POST /search`** as defined in `ard.openapi.yaml`: request `query {text, filter}`, `federation`, `pageSize` (default 10; the spec text says max 100, the OpenAPI file has no maximum), `pageToken`; response `results` (each `identifier`, integer `score` 0 to 100, `source` URI, plus the entry fields) and `pageToken`; `referrals` only in referral mode, so never. Filters: OR within a term, AND across terms, `publisher` derived from the URN, any dotted entry path usable. Ranking is behind `SearchBackend.rank` for a later embedding backend. The Python function takes `text` and `filter` directly; the nested `query` wrapper is an HTTP concern. Not implemented: `/explore`, `GET /agents`, semantic search, A2A delegation, `/.well-known/ard.json` serving.
51. **Remaining gaps.** The OpenAPI file is at version 0.5.0 while the spec is v0.91, so the two disagree in places (for example `pageSize` max); where they differ the spec text is followed. Not run: the `conformance-test` CLI from the ARD repo (it needs a runtime Themis does not have). Appendix C states no case or length rules. ADR 0001 (Observal) is consistent with this design: it also uses `urn:air:<domain>:<kind>:<id>`, a placeholder `.local` publisher and no single-label hosts. ADR 0002 only affects imported A2A agents, which Themis does not have. Supersedes the earlier "not verified" notes.

## Phase 4

52. **Charts: Rich-rendered bars plus Textual `Sparkline`.** No plotext dependency. Bars are Unicode block characters in `Static` tables (`analytics.bar`), time series also get a `Sparkline`. Both render identically in the terminal and in `textual serve`, need no extra package, and are testable with the pilot.
53. **Time bucketing.** A session counts wholly toward the day, ISO week or month it started in (transcripts hold no per-day usage in the summary). Token splits by model use the per-model buckets and so are exact; the cost split by model uses the same price table per model. Cost is always "API-equivalent estimate"; unpriced models mark it incomplete with a `+`.
54. **Analytics are pure functions** (`themis/analytics.py`, no UI imports) shared by the Insights screen and the reports. Windows: `7d`, `30d`, `90d`, all in the UI; `--since` accepts `Nd`, `Nw`, `Nm` (30 days), `Ny` (365 days) or a date.
55. **Advisor** (`themis/advisor/`) is pure: `run_advisor(data, now, profile)` reads loaded data and returns `Advice` objects (rule, severity, confidence, evidence, files, goal, estimated tokens saved per session and per month, prompt). A test snapshots a whole profile tree before and after and asserts nothing changed. Thresholds are in `[advisor]` in `config.toml`.
56. **Advisor rules and their honest limits.**
    1. Unused skills: judged from `Skill` tool calls and typed slash commands only, per profile, over `unused_days` (60). Needs sessions in the window; with none, no finding (absence of use proves nothing). Grouped per profile and origin (user, synced, one plugin) to avoid hundreds of findings. Confidence follows the number of sessions in the window (30+ high, 10+ medium).
    2. Unused MCP servers: tool schema size is not recorded locally, so no token estimate is given (the finding says so) rather than inventing one.
    3. Startup overhead: skill/agent/command name plus description and user CLAUDE.md, ranked by contributor; MCP schemas and project CLAUDE.md are excluded and the evidence says so. The skill listing is capped by Claude Code, so the sum is an upper bound.
    4. Identical copies are reported only for user-level resources: app-synced copies are managed by the desktop app and would be re-synced over a symlink. One aggregated finding. Near-duplicates: Jaccard word overlap of descriptions at or above `near_duplicate` (0.85) or equal hashes under different names.
    5. Drift: one finding per resource; synced copies get a note to re-sync rather than edit.
    6. CLAUDE.md: size over `claude_md_max_tokens` (2000, estimate), and paragraphs of 60+ characters repeated across different files.
    7. High context: peak at or above 80% with zero compactions. The window is inferred (decision 7), so the evidence carries a caveat; no token saving is given.
    8. Low cache hit rate: under 50% with at least 50k input-side tokens. Pattern from summary data only (average gap between replies over 5 minutes, compaction, very short session). "Avoidable tokens" is a rough figure against an 80% target and confidence is low; with the 1-hour cache TTL common on subscriptions the idle-gap pattern is only a possibility.
    9. Descriptions: longer than `skill_desc_max_chars` (500), and pairs with word overlap between `description_overlap` (0.6) and `near_duplicate`.
57. **Real-data corrections to the advisor.** Running it on the real profiles first produced 81 findings; two causes were fixed: `skillOverrides` keys for synced skills were not matched (so disabled skills were still reported), and identical synced copies produced 52 separate findings. Now 30.
58. **Prompts** (`advisor/prompts.py`) are self-contained: finding, every involved profile with its exact `CLAUDE_CONFIG_DIR`, evidence, exact files, goal, then instructions to read the files, propose the smallest change as a diff first, ask for confirmation before touching anything outside the project or inside any `~/.claude*` directory, back up, and never print secrets. They pass through secret redaction.
59. **Redaction is split in two.** `redact_secrets` masks known secret shapes (keys, tokens, bearer strings, URL credentials) and is safe for whole documents; `redact_text` adds the `NAME=value` heuristic for secret-looking names and is for free-text items. Redacting a whole report with `redact_text` turned "Tokens: 2.2B" into `***REDACTED***`, so reports and advisor output use `redact_secrets` on the document and `redact_text` on evidence, messages and project names.
60. **Reports** (`reports/`) hold counts, ids, project folder names and configuration metadata only: no topics, prompts, snippets, tool output or CLAUDE.md text beyond a 70-character repeated-paragraph preview in advisor evidence (redacted). Written to `~/.themis/reports/` (or `--out`), audited. HTML is a single file with inline CSS, no scripts and no external requests. The Insights screen exports through the same code.
61. **Unavailable profiles.** A profile directory that vanishes or becomes unreadable no longer crashes discovery or scans (it did: `PermissionError`). Discovery keeps it with `Profile.problem`; `usable()` re-checks the disk before each scan; unusable profiles are skipped, shown as a toast in Sessions, and reported as a `profile-unavailable` doctor error. A scan interrupted mid-way records an error instead of raising.
62. **Packaging.** Version `0.1.0` (`themis version`, `themis --version`, `themis.__version__` from package metadata). Built wheel contains `themis.tcss` and the console script. `pipx` is not installed on this machine, so `pipx install .` was verified through its equivalent: `uv tool install` of the built wheel into a temporary tool directory, then `themis version`, `themis profiles` and `themis web` (answers HTTP 200 after about 8 seconds on a cold start). GitHub Actions CI (`.github/workflows/ci.yml`) runs ruff, ruff format check and pytest on macOS and Ubuntu with Python 3.12 and 3.13, then builds and smoke-installs the wheel.
63. **Performance on real data** (about 330 MB of transcripts, 69 sessions, 4 profiles, read-only, temporary `THEMIS_HOME`): cold scan with a process pool 1.5 s wall and 55 MB peak memory; warm session load 0.05 s (0.27 s for the whole `themis sessions` CLI); warm resource scan plus doctor 0.6 s; advisor 0.06 s; report 0.07 s; in-process peak 49 MB. Nothing needed fixing. Not measured: the 5 GB scale from the plan.
64. **End-to-end smoke.** `tests/test_e2e.py` runs every write action (rename, tag, export, archive, delete, restore, copy, move, resource tags, plugin and MCP toggles, settings edit, two promotes, report export, manifest) in a temp tree and asserts the audit log, the backups, and that no audit path points at the real home. `scripts/smoke_real_copy.py` repeats the resource writes on a redacted temp copy of the real configuration (symlinks dereferenced, MCP definitions masked, no transcripts, no account data) and then proves the real `settings.json` files, skills listings, shared skills and audit log are unchanged. A read-only pass on the real profiles followed (see the release summary).
65. **Roadmap (not implemented):** semantic search over resources; A2A delegation across profiles; optional LLM session summaries; exposing Themis as an MCP server; optional Observal OTLP ingest.
66. **UI test flake fixed.** `test_retention_banner_and_archive_all_at_risk` failed once in a full run and, under CPU load, 9 times in 12 when run alone. Cause: the test clicked the button before layout had settled (the click landed on the header's command-palette icon) and checked the modal after one fixed pause. The UI tests now wait for conditions (`screen_is`, `click_ready` in `tests/test_ui.py`) instead of fixed pauses. After the change: 40 consecutive runs under heavy load without a failure, and the full suite passes under load. No application change was needed.
67. **Release gate.** v0.1.0 is tagged only after `ruff check`, `ruff format --check` and the whole pytest suite pass on the commit that carries the tag.

### Open issues at v0.1.0

- ARD: the repo's `conformance-test` CLI has not been run against a generated manifest; `representativeQueries`, `trustManifest` and `/.well-known/ard.json` serving are not implemented (decision 51).
- Context window size is inferred, so a 1M-window session that never exceeded 200k can show an inflated percentage (decision 7). The high-context advisor rule says so.
- Cost, "saves tokens" and startup-overhead figures are estimates (4 characters per token, API list prices).
- App-synced skills (`skills/synced/`) are managed by the desktop app; Themis reports their drift but does not offer to promote them.
- MCP tool schema cost is not measurable from local files, so unused-MCP findings carry no token estimate.
- Not tested: Linux and Windows (CI runs Linux, but clipboard and resume helpers assume macOS tools), the 5 GB transcript scale, and `pipx` itself (verified through `uv tool install`).

## Manifest regeneration (after v0.1.0)

68. **Manifest now validated against the real ARD schema.** The unmodified `ard-entry.schema.json` from `ards-project/ard-spec` (`spec/schemas`, fetched 2026-10-27 from `main`, no commit SHA visible) is vendored at `src/themis/registry/ard-entry.schema.json` and checked by `themis registry validate` and by `themis registry manifest`, which refuses to write an invalid manifest. The schema immediately exposed a real bug in decision 49: `metadata` values must be scalars (string, number, boolean or null), and the manifest put an object under `metadata.themis`. Metadata is now flat scalar keys (`themis_origin`, `themis_scope`, `themis_profiles` comma-joined, `themis_content_hash`, `themis_tokens_startup`, `themis_tokens_full`, `themis_variants` as `hash=profiles;...`, `themis_queries`); search filters use `metadata.themis_profiles`, `metadata.themis_scope`, and a comma-joined metadata string matches per item. `jsonschema` is now a runtime dependency.
69. **`representativeQueries` are generated, heuristically.** ARD says entries SHOULD carry 2 to 5; the conformance tester warns otherwise. Themis has no LLM, so `registry/queries.py` extracts the "use when ..." clauses of a description, falls back to its first sentence, then to templated phrases ("use the X skill"), redacts them, and records `themis_queries: heuristic` in the metadata. Quality varies: some are fragments of the description rather than natural requests. All 228 real entries now have 2 to 5.
70. **Still not published:** `trustManifest` (Themis cannot prove a workload identity for a local, unsigned registry; it is optional and only requires an identity aligned with the publisher when present) and `capabilities`. `updatedAt` is also left out. Serving at `/.well-known/ard.json` stays out of scope (no listener beyond the UI).
71. **Conformance status.** Run against real data: 228 entries, 0 schema errors, 0 warnings, identifiers unique, publisher a fully qualified domain. The repo's own `conformance-test` CLI was not executed (fetching and running third-party code was not requested); `themis registry validate` implements its schema check, identifier-uniqueness and publisher checks, and the two representativeQueries warnings from section D.2 of the spec. Supersedes the "conformance-test not run" part of decision 51 and of the v0.1.0 open issues.

## TUI scan fix (after v0.1.0)

72. **Process pool gets the real stderr while it starts.** In the TUI the Sessions scan runs in a Textual worker thread, and Textual replaces `sys.stderr` with a capture object whose `fileno()` is `-1`. `ProcessPoolExecutor` starts multiprocessing's resource tracker, which passes `sys.stderr.fileno()` to `spawnv_passfds`, so any scan with `POOL_THRESHOLD` (6) or more uncached sessions failed with `ValueError: bad value(s) in fds_to_keep` ("Load failed" in the status line). `sessions/cache.py` now wraps the pool in `_real_stderr()`, which swaps in `sys.__stderr__` only when the current stderr has no usable fd, and restores it afterwards. Alternatives rejected: a thread pool (parsing is CPU-bound, so no speed-up) and serial parsing (slow on large profiles). A subprocess regression test fakes Textual's stderr, because the resource tracker is a per-process singleton and an in-process test would not reproduce the failure once it had started.

## Web frontend (after v0.1.0)

73. **`themis web` is now a real web app, not the terminal UI in a browser.** The Textual app piped through xterm.js looked and behaved like a terminal. `themis.web` is an aiohttp server (127.0.0.1 only) with a JSON API over the existing core and a static vanilla-JS single page (no CDN, no network, system fonts), pure black and white. `themis web --terminal` keeps the old textual-serve mode. The core stays UI-free; `web/api.py` only shapes data.
74. **Usage first.** The landing page is token and cost over time, then most-used skills, tools, commands, MCP servers and subagents, with a prompt to review installed-but-unused skills. Resource tables sort by invocations and filter Used / Unused. The detail drawer is a grid column with its own scroll (an overlay only below 1180px), so it never covers the list.
75. **Toggles go through the confirm-token write path.** A switch calls `/api/toggle` as a dry run, shows the diff in a dialog, and only the Apply button resends with `apply: true`, which makes the server pass `settings.CONFIRM` to `set_plugin_enabled` / `set_mcp_enabled` (backup and audit log as before). Only plugins and user-scope MCP servers have switches; the web app has no session delete, move or archive.
76. **Local-server guard.** Requests need a `Host` of `127.0.0.1:PORT` or `localhost:PORT`; POSTs also need a matching `Origin`. This blocks DNS rebinding and cross-site POSTs to the write endpoint. Responses send `no-store` and a same-origin CSP. Tested in `tests/test_web.py` on synthetic profiles only.
77. **v0.2.0** ships the web app (decisions 73-76). Same release gate as 67: ruff check, ruff format --check and the whole pytest suite pass on the tagged commit.
78. **v0.2.1:** plugins and hooks show "not tracked" instead of "unused" in the web app. Transcripts record no plugin or hook invocations, so calling them unused (found by running the web app on real profiles) was wrong.
79. **Terminal UI restyled to match the web app.** A registered Textual `Theme` ("themis": black background, near-white text, greys) replaces the green/blue palette. Colours that carried meaning in Rich styles (scope, on/off, diff, severity, context %) now use weight and decoration instead: bold for emphasis and "on", dim and strike for "off" and removals, underline for plugins, reverse for errors and drift. Buttons are outlined with a solid white primary. Behaviour, bindings and widget ids are unchanged; no ids were renamed.
80. **v0.2.2** ships the monochrome terminal UI (decision 79). Same release gate as 67.
